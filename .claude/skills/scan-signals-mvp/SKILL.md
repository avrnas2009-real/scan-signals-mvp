# scan-signals-mvp — единый вызов «данные → правила → результаты»

MVP-скилл автономного проекта scan-signals_MVP. Один вызов = полный цикл:
прочитать инструменты, собрать данные TradingView MCP, проверить каталог
правил ТА, сформировать черновики постов, записать журнал, вернуть сводку.

## Жёсткие границы

- Ничего не отправлять вовне (никаких fetch/curl/API, bot token, chat_id).
- Не выходить за пределы рабочей папки проекта (`scan-signals_MVP/`).
- Не отправлять удалённые или переименовывать файлы.
- Цифры — только из данных MCP TradingView или расчёта `temp/tv-indicators.js`
  / `temp/ta-tools.js` по этим барам. MCP вернул ошибку/пусто → в отчёт с
  пометкой «нет данных», без выдуманных значений; правило по этому
  символу/ТФ пропускается.

## Алгоритм (по шагам, единый вызов)

1. **Watchlist.** Прочитать `notes/watchlist.md` (символы EXCHANGE:TICKER,
   ТФ 1h/4h/1d). Пустой/сломанный — сообщить и остановиться.

2. **Каталог правил.** Прочитать актуальный файл из `strategies/`
   (максимальная дата в имени). Не применять правила по памяти.

3. **Данные.** Для каждого символа × ТФ через MCP:
   - `mcp-tv-get-ohlcv` (независимые вызовы, одним блоком; бары последних
     ~150–270 свечей — по ТФ);
   - `mcp-tv-get-symbol-data` текущая цена/объём (если доступно).
   Бары сохранить в `temp/<TICKER>_<TF>.json` (сырые) и
   `temp/<TICKER>_<TF>.csv` (заголовок open, high, low, close, volume).

4. **Расчёты.** Индикаторы правил — только через `node temp/tv-indicators.js`
   (EMA, RSI, ADX, ATR — по аргументам CLI) по сохранённым CSV.
   Вспомогательно (не обязательно): `temp/ta-tools.js` rw/pips/hsar для
   уровней R1. Скрипты не изменять.

5. **Детекция (правила из каталога, все условия обязательны).** По каждому
   символу × ТФ проверить R1, R2, R3 из активной версии каталога. Правило
   сработало только при выполнении ВСЕХ условий; подтверждения technicals —
   по MCP, при их недоступности — локальные замещения из каталога (v1.1).

6. **Фильтр качества:** уровень правивла не совпадает с данными (расхождение
   > 0.05%); аномальна волатильность (последняя свеча > 3×ATR14);
   дедупликация: тот же тикер + событие в `journal/signals-log.md` за
   последние 4 часа — пропуск.

7. **Черновики постов.** Для оставшихся событий (приоритет R1 > R2 > R3,
   максимум 3 за скан) — по формату tg-post (стиль signal, JSON
   `telegram/outbox/YYYY-MM-DD-HHMM-<TICKER>-<event>.json`, `status: draft`):
   уровни, цены, RSI — только из данных шага 3/4. Формулировки — «жмём ретест»,
   «если вернёмся под уровень» — не рекомендации; дисклеймер «это не торговый
   сигнал».

8. **Журнал.** После черновиков: в `journal/signals-log.md` добавить запись
   `дата-время | тикер | ТФ | событие | ключевые значения | имя черновика`.
   0 событий — строк в журнал не добавлять.

9. **Отчёт в чат.** Обязательно вернуть:
   - сколько символов/ТФ проверено, из чего исключены по ошибкам данных;
   - сработавшие правила (символ/ТФ/правило/значения) или честный «0 событий»;
   - пути к созданным черновикам и запись в журнале;
   - какие данные недоступны (technicals null и т.п.).

## Важно

- 0 сработавших правил — нормальный результат. Условия правил не ослаблять,
  чтобы «что-нибудь найти».
- Если правило не проверяемо из-за недостающих данных — пропустить его с
  пометкой в отчёте, не подменять значения.
- Список «не делать» CLAUDE.md проекта действует всегда; шаги данного
  алгоритма не создают исключений.
- Черновики по тестовым данным — только по явному слову «тест» пользователя.
