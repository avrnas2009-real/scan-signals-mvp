# scan-signals-mvp — агентный сканер сигналов по сырьевым фьючерсам

MVP-проект агентной системы: один вызов скилла `scan-signals-mvp` в Claude Code
проходит полный цикл — **данные TradingView → правила теханализа → черновики
постов → журнал** — и возвращает сводку в чат.

Ничего не отправляется вовне: телеграм-канал, API, уведомления — вне MVP.
Продукт скилла — только draft-файлы на диске и отчёт в чате.

---

## Как это работает

```
пользователь: «scan-signals-mvp» / «просканируй рынок»
        │
        ▼
┌─ Скилл .claude/skills/scan-signals-mvp/SKILL.md ──────────────────────┐
│ 1. watchlist   → notes/watchlist.md (5 инструментов × 1h, 4h, 1d)      │
│ 2. правила     → strategies/ (машинно-читаемый каталог, актуаль-
│                   ный файл = максимальная дата в имени)               │
│ 3. данные      → MCP-сервер TradingView: OHLCV по каждой комбинации
│                   «символ × ТФ» → temp/<TICKER>_<TF>.json/.csv        │
│ 4. расчёты     → temp/tv-indicators.js (RSI, EMA, ADX, ATR…),
│                   temp/ta-tools.js (RW, PIPs, HSAR) — Node, без завис.│
│ 5. детекция    → проверка КАЖДОГО условия КАЖДОГО правила             │
│ 6. фильтры     → подтверждение старшим ТФ, порог 0.05%,
│                   волатильность < 3×ATR, дедупликация 4 ч             │
│ 7. черновики   → telegram/outbox/YYYY-MM-DD-HHMM-<TICKER>-<event>.json │
│                   (status: draft, ≤ 3 за скан, приоритет R1>R2>R3)     │
│ 8. журнал      → journal/signals-log.md (сработавшие события)          │
│ 9. отчёт       → сводка в чат: проверки/события/файлы/ошибки данных   │
└───────────────────────────────────────────────────────────────────────┘
        │
        ▼
пользователь видит: сводку в чате + файлы в outbox/ и journal/
```

Ключевой принцип: **0 сработавших правил — нормальный результат.**
Условия правил не ослабляются, чтобы «что-нибудь найти»; правило срабатывает
только при выполнении всех своих условий.

## Что внутри

| Путь | Назначение |
|------|-----------|
| `.claude/skills/scan-signals-mvp/SKILL.md` | скилл — единый алгоритм всех 9 шагов |
| `CLAUDE.md` | правила проекта: границы, работа с данными, нейминг |
| `notes/watchlist.md` | инструменты и рабочие таймфреймы |
| `strategies/` | машинно-читаемый каталог правил (актуальный файл — с максимальной датой) |
| `temp/` | рабочий каталог: сырые бары (JSON/CSV), копии расчётных скриптов, хелперы |
| `telegram/outbox/` | черновики постов (`status: draft`) — пишутся только скиллом |
| `journal/signals-log.md` | журнал сработавших правил и источник дедупликации |
| `.gitignore` | бары, результаты прогонов и черновики в репозиторий не входят |

### Детекторные правила (v1.1)

- **R1 `level_break`** — закрытие рабочего ТФ выше/ниже локального экстремума
  последних 20 баров старшего ТФ; порог значимости ≥ 0.05%; подтверждение —
  technicals-rating старшего ТФ (или локальный заместитель: close к EMA50).
- **R2 `ema_cross`** — пересечение EMA20/EMA50 на последнем закрытом баре;
  подтверждение — ADX > 20 (тренд не во флете).
- **R3 `rsi_zone`** — возврат RSI(14) из крайних зон (<30 или >70) в пределах
  последних 5 баров; подтверждение — цена на стороне EMA20 предполагаемого
  разворота.

Общие отсечения для всех: свеча > 3×ATR(14) — не постить; тот же тикер+событие
за 4 часа — дедупликация по `journal/`; максимум 3 черновика за скан.

## Запуск

Требуется Claude Code с настроенным MCP-сервером TradingView (`mcp-tradingview`)
и Node.js ≥ 18 (расчётные скрипты — чистый Node, без зависимостей).

```text
# в рабочем каталоге проекта
> scan-signals-mvp          # или: «просканируй рынок»
```

Скилл сам читает watchlist/правила, сам пишет данные в `temp/`, создаёт
черновики в `outbox/`, дописывает журнал и печатает отчёт. Черновики по
тестовым данным — только по явному слову «тест».

## Формат черновика

JSON-файл в `telegram/outbox/` (`status: draft`): событие (`type/ticker/
timeframe/level/price/direction`) + готовый текст поста в Telegram-HTML
(стиль `signal`). Формулировки — сценарии наблюдения («жмём ретест», «если
вернёмся под уровень»), без торговых рекомендаций; пост завершается
дисклеймером «это не торговый сигнал».

## Границы и содержательные правила

- Все цифры (уровни, цены, RSI, EMA, ADX) — только из данных MCP TradingView
  или расчёта скриптов по этим барам. Ошибка/пустой ответ MCP → в отчёте
  пометка «нет данных», значения не подставляются.
- Нет отправки вовне (никаких fetch/curl/API, токенов бота) — только файлы.
- Значения по незакрытой свече — предварительные; скилл считает по последним
  закрытым барам.
- Паттерны правил писаны под дневной масштаб; события на 1h/4h помечаются
  масштабом. Не инвестиционный совет.
