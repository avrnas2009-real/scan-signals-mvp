Я начинающий трейдер. Сейчас торгую сырьевыми фьючерсами. Рабочие таймфреймы: 1h, 4h, 1d.

# Проект: scan-signals_MVP
Обособленный MVP-проект сканера сигналов. Один вызов скилла
`scan-signals-mvp` — полный цикл: данные TradingView MCP → правила ТА из
`strategies/` → 0–3 черновика поста в `telegram/outbox/` → запись в
`journal/` → отчёт в чат. Скилл самодостаточен: свои копии расчётных
скриптов в `temp/`, свой watchlist и каталог правил. Отправка в канал —
за пределами проекта (наследник — signals-agent).

# Структура проекта
- `notes/watchlist.md` — инструменты и ТФ.
- `strategies/` — машинно-читаемый каталог правил (актуальная версия —
  файл с максимальной датой в имени).
- `.claude/skills/scan-signals-mvp/` — единый скилл-цикл.
- `telegram/outbox/` — черновики постов (`status: draft`). Сюда пишет только скилл.
- `journal/signals-log.md` — журнал сработавших правил и дедупликация.
- `temp/` — сырые бары (JSON/CSV) и расчётные скрипты-копии
  (`tv-indicators.js`, `ta-tools.js`) — временные файлы, папку не удалять.

# Как работаем
- Сначала показываешь план, всегда уточняешь детали перед стартом.
- Работать самостоятельно можно только с моего разрешения.
- Проверка результата: отчёт, список изменённых файлов, ссылки на источники.

- Без длинных вступлений — сразу к делу.

# Содержательные правила
- Цифры (уровни, цены, RSI, EMA, ADX) — только из данных MCP-сервера TradingView
  или расчёта копий скриптов по этим барам. Ошибка/пустой ответ — сообщить, не подставлять.
- Не формулировать торговые рекомендации от лица канала: описывать сценарий
  наблюдения («жмём ретест», «если вернёмся под уровень»). Дисклеймер
  «это не торговый сигнал».
- В конце постов-сигналов не обещать прибыль и не давать инвестиционных советов.
- Дедупликация: один сигнал по одному тикеру — сверяться с `journal/` (4 часа).
- Скрипты в `temp/` не изменять; рабочие копии не создавать без нужды.
- Скрипты считают по close последнего бара — на незакрытой свече значения
  предварительные.
